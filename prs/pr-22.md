## Why

Tasks often need to move: from one journal day's Todo to another, into a
page as a checklist, or out of AFFiNE into a Markdown note. Copying table
rows used to give only cell text, so the hierarchy and ticks were lost, and
the List view (the Journal Todo's view) had no way to select rows at all.

## What changes

**Selecting rows in the List view** (new; tables already have it):

- **Escape** while typing in a row selects that row.
- **Shift+↑/↓** extends the selection, **↑/↓** moves it, **Enter** edits
  the row again, **Escape** selects the whole database block (as in a
  table, so Enter then adds a paragraph after it).
- **Clicking a row's drag handle** selects it; **Shift+click** selects a
  range, **Ctrl/Cmd+click** adds or removes a row.

**Copying.** With whole rows selected (table or List view), copy writes:

- **the rows themselves:** title, indent level, done state and the other
  columns by name. Pasted into a table or List view (another Journal Todo,
  any task table), they become **new** rows after the last selected row,
  or after the row being typed in, keeping the hierarchy and status. They
  are copies, not references.
- **an AFFiNE to-do list:** pasted into a page, the rows become to-do items
  nested by level, with the ticks kept.
- **a Markdown task list** as plain text: `- [ ] task`, `- [x] done`, two
  spaces per level.
- **a nested checkbox list** as HTML, for rich-text apps.

Copying cells, or rows from a table without a task status, works as before.
A toast says how many rows were copied.

## How it works

- `data-view/src/view-presets/shared/rows-clipboard.ts`: reads rows into a
  plain shape, renders the three formats, inserts copied rows (shared so
  the List view can use it next).
- The table's clipboard controller writes them on copy of a row selection,
  and reads `blocksuite/database/rows` first on paste.
- The page paste uses an AFFiNE block snapshot (`BLOCKSUITE/SNAPSHOT`),
  because the HTML and Markdown importers drop the ticks.
- `DatabaseBlockDataSource.setRowHierarchyLevel` sets a pasted row's level.
- List view: a `list` view selection (rows, anchor, focus) in the database
  selection; `ListClipboardController`. The selected rows' keys are handled
  on the focused row, not with the view's hotkeys: those can be registered
  at the page's level, where the page's own Shift+arrow ran first.
- Escape to the block uses `selectBlock` from `fix/database-escape-to-block`
  (F-13), so that is a second base.

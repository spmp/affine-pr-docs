## Why

Tasks often need to move: from one journal day's Todo to another, into a
page as a checklist, or out of AFFiNE into a Markdown note. Copying table
rows used to give only cell text, so the hierarchy and ticks were lost, and
the List view (the Journal Todo's view) had no way to select rows at all.

## How to select

### In a table

| To select | Do this |
| --- | --- |
| **One row** | Hover the row and click the **checkbox** at its left. Or, while editing a cell, press **Escape** twice: the first leaves editing (the cell is selected), the second selects the cell's row. |
| **More rows** | Click more rows' checkboxes (each click adds or removes that row), or with rows selected press **Shift+↑ / Shift+↓**. |
| **A block of cells** | Click a cell, then **Shift+click** another, drag across cells, or press **Shift+arrow keys**. Escape then turns the cells' rows into a row selection. |
| **The whole database** | With rows selected, **Escape** once more (F-13, `fix/database-escape-to-block`). **Enter** from there adds a paragraph after it. |

### In a List view (the Journal Todo)

| To select | Do this |
| --- | --- |
| **One row** | While typing in a row, press **Escape**. Or hover the row and **click the grip** (the small handle at its left). The row turns light blue. |
| **More rows** | **Shift+↑ / Shift+↓**, **Shift+click** another row's grip (a range), or **Ctrl/Cmd+click** a grip (add or remove one row). |
| **Move the selection** | **↑ / ↓** (without Shift). |
| **Back to typing** | **Enter** edits the row the selection last moved to; clicking into any row's text also ends the selection. |
| **The whole database** | **Escape** with rows selected. |

### On mobile (Journal Todo and tables)

| To | Do this |
| --- | --- |
| **Start selecting** | **Long-press a row** (hold still about half a second). The row turns light blue and a bar appears at the bottom: *N selected · Copy · Select all · Done*. |
| **Add or remove rows** | **Tap** them while selecting (taps don't start editing then). |
| **Copy** | **Copy** in the bar. Same formats as on desktop: a to-do list from the Journal Todo, a table from a table. |
| **Stop** | **Done**. |
| **Paste** | Long-press inside a row's text, **Paste**: copied rows go in as new rows after that row. In a page, long-press, **Paste**. |

Long-pressing directly on a row's text also starts iOS's own text
selection; selecting rows clears it. Pressing on the row's empty space or
fields avoids it.

The page's own drag-select (the grey square from dragging in the margin)
selects whole blocks, not rows inside a database; it can't select List
view rows. Making it do so is a possible follow-up.

Not done yet: **Delete/Backspace** on selected rows, **Tab** to indent
them, and drag-selecting text across rows.

## What copying gives, and where it pastes

**Ctrl/Cmd+C** with rows selected. A toast says how many rows were copied.

| Copied from | Pasted into a table or List view | Pasted into a page | As plain text (other apps) | As HTML (rich-text apps, spreadsheets) |
| --- | --- | --- | --- | --- |
| **Table rows** | New rows | A **new database** holding just those rows: all columns, indent levels and done state; the current view, without its filter | A **Markdown table** of the shown columns (done column as `[x]` / `[ ]`) | An HTML **table** of the shown columns |
| **List view rows** (Journal Todo) | New rows | A **to-do list**, nested by level, ticks kept | A **Markdown task list**: `- [ ] task`, `- [x] done`, two spaces per level, the List view's shown fields after the title, **tab-separated** | A nested checkbox list, fields after the title |
| **One column of cells** (table) | Into the cells, as before | A bulleted list (from the text) | `- value` per line; empty cells left out | (none) |
| **Several columns of cells** (table: click a cell, Shift+click another) | Into the cells, as before | A **new database** of just those rows and columns (task levels kept) | A **Markdown table** of those columns | An HTML **table** of those columns |

**New rows** means copies, not references: title, indent level, done
state and the columns the target has (matched by name). They go:

- after the **last selected row** when rows are selected, or
- after the **row you are typing in**, when you paste while editing a cell
  or a List view row (the text is not pasted into the cell), or
- after the **focused cell's row** when a cell is selected.

They keep their levels relative to each other; the first pasted row takes
the level of the row it goes after. Pasted rows are selected afterwards.

Examples. Rows `A` (done), `B` (indented under A), `C`, with a Notes
column (`note a` on A):

From a table, as plain text:

```
| Title | Status | Notes  |
| ----- | ------ | ------ |
| A     | [x]    | note a |
| B     | [ ]    |        |
| C     | [ ]    |        |
```

The columns are padded so they line up.

From a List view showing Notes, as plain text (`→` is a tab):

```
- [x] A→note a
  - [ ] B
- [ ] C
```

### Open points for the Markdown work (PRs 60+)

These plain-text forms are a first choice, to be revisited with the export
and import work (see [Plain-text formats](../plain-text-formats/)):

- A Markdown table can't show indent levels (cells drop leading spaces);
  the table form loses the hierarchy. The database pasted into a page keeps
  it.
- The List view's tab-separated fields have no header, so their meaning is
  positional (the List view's field order).
- Cell text with line breaks: `<br>` in the Markdown table, a space in the
  tab-separated fields.
- Pasting AFFiNE's own plain text back (a Markdown table or `- [ ]` lines)
  goes through the page's Markdown import, not back into rows.

## How it works

- `data-view/src/view-presets/shared/rows-clipboard.ts`: reads rows into a
  plain shape (`rowsToClipboardRows`), renders the formats, writes them
  (`copyRowsToClipboard(logic, rowIds, 'table' | 'list')`), reads copied
  rows back (`readClipboardRows`) and inserts them (`insertClipboardRows`).
- Clipboard types: `blocksuite/database/rows` (the rows, for tables and
  List views), `BLOCKSUITE/SNAPSHOT` (what a page paste reads first; a
  database or a to-do list), `text/plain`, `text/html`. The HTML and
  Markdown importers would drop ticks and columns, hence the snapshot.
- `DatabaseBlockDataSource.rowsSnapshot(rowIds, viewId)`: the database as a
  block snapshot with only those rows and that view (filter cleared).
- `DatabaseBlockDataSource.setRowHierarchyLevel` sets a pasted row's level.
- Table: the clipboard controller writes rows on copy of a row selection
  and reads copied rows first on paste; a capture-phase `paste` listener
  takes copied rows while a cell is being edited (the cell's editor would
  paste them as text). One column of cells copies as a `- ` list.
- List view: a `list` view selection (rows, anchor, focus) in the database
  selection; `ListClipboardController`; a capture-phase paste on each row.
  The selected rows' keys are handled on the focused row, not with the
  view's hotkeys: those can be registered at the page's level, where the
  page's own Shift+arrow ran first.
- Escape to the block uses `selectBlock` from `fix/database-escape-to-block`
  (F-13), so that is a second base.

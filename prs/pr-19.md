## Why

AFFiNE has two task surfaces that don't talk to each other:

- **To-do lists** are quick to type and nest, but have no due dates, no
  views and no overview.
- **Database tables** have views (Kanban, Calendar) and properties, but
  feel nothing like a checklist.

Daily journaling makes this worse. Yesterday's unfinished tasks stay on
yesterday's page, and every day starts from scratch.

This PR makes a database work as a to-do list with hierarchy, and builds a
**Journal Todo** on top. The Journal Todo is one task table shown on every
journal page, filtered to that day, with unfinished tasks carried forward.

## What changes

### To-do lists

- **Nested completion.** Ticking every child of a to-do item ticks the
  parent. Unticking a child unticks the parent again. It works up through
  every level of nesting.
- **Indent and outdent with the keyboard:** Cmd/Ctrl+Shift+. and
  Cmd/Ctrl+Shift+, (also Cmd/Ctrl+> and Cmd/Ctrl+<).
- **To-do list settings.** A **Settings** button in the to-do list's toolbar
  opens per-list settings:
  - **Optional fields** shown on each item, such as a cost or a date. Types:
    text, number, date, select, multi-select and progress.
  - **Field layout:** inline, aligned or right.
  - **How ticks map to a database status:** the status column's name, and the
    labels for done and not done.
- **To-do list → database.** A nested to-do list can be turned into a
  database. Order, parent/child structure and the optional fields are kept,
  and ticks become the status column.

### Databases as task lists

- **Hierarchy in Table view.** Rows are indented. Drag a row, use the row
  menu's **Indent Row** / **Unindent Row**, or press Cmd/Ctrl+Shift+. and
  Cmd/Ctrl+Shift+, to change its level.
- **Parent status follows its subtasks.** Set per table under **Parent status
  behavior** in the table and Kanban menus, with global defaults in settings:
  - **Done roll-up:** a parent becomes Done when all its subtasks are Done.
  - **In-progress promotion:** a parent moves to In Progress when any subtask
    starts.
  - **Auto-demote:** a parent that was made Done automatically goes back when
    a subtask is reopened. A parent you set to Done yourself stays Done.
  - **Manual Done cascades:** setting a parent to Done by hand also sets all
    its subtasks to Done.

  Each rule can be turned off.
- **Kanban for tasks:**
  - **Columns** come from a configurable list of `Label:status` pairs, such
    as Todo, In Progress and Done. Moving a card between them changes its
    status, and the roll-up rules above apply.
  - **Filter by level** (All, 0–5), and **Show children** or **Show
    descendants** of a chosen parent.
  - Cards show their parent and level.
- **Status works the same everywhere:** in the to-do list, Table, Kanban and
  List views.
- **Move to another page.** **Move to page…** in the table's menu moves it to
  another page. Every reference keeps working, including after the original
  page is deleted.

### Settings: List, Database, and Kanban

A new section in **Settings → Editor** holds the global defaults:

- optional list fields and their layout
- database status column, Done tag and Not-done tag for converted lists
- parent Done roll-up, parent In Progress roll-up, auto-demote, manual Done
  cascade
- Kanban columns
- **Highlight after due date:** Highlight, Hide or Off. Each table can
  override it.
- **Hide from calendar when done**
- **Show "Due date" in Journal todo:** whether a new Due date column starts
  visible

### List view: a database that behaves like a to-do list

- **List view** shows a database as a checklist. A List view on an empty
  table creates to-do rows.
- **Native list editing:**
  - Enter splits a row; Enter on an empty row outdents it.
  - Backspace at the start of a row merges it into the row above; Delete at
    the end merges the next row in.
  - Cmd/Ctrl+Z and Cmd/Ctrl+Shift+Z undo and redo.
  - Cmd/Ctrl+A selects all.
  - Selecting text and deleting it works.
- **Drag rows** by the left-hand handle to reorder or re-indent them, as with
  native to-do items.
- **Done animation.** A tick animation plays when a task is done.

### Database references with their own view

Building on [pr/18](../pr-18/):

- **Their own view.** `/Table (own view): <name>` and `/Reference (own view)`
  reference a table with **independent** views and filters. Changing them
  doesn't affect the source table or other references.

### Journal Todo

- **One shared task table.** `/Journal Todo` inserts the journal's task list:
  a reference to one shared task table, filtered to the current journal day.
  Every day's journal uses the same table, so all tasks stay in one place.
- **Choose the table:**
  - **Set Journal Todo Table** makes any existing table the source, such as
    a task list you already keep.
  - **New Journal Todo Table** creates a fresh one. If it replaces an earlier
    Journal Todo table, AFFiNE offers to **copy the unfinished tasks**
    across, with their status, values and hierarchy. The old table is left
    untouched.
- **Templates.** Put a Journal Todo in the journal template. Every new day's
  journal then gets one pointing at the **current** table, even if the
  template was made before the table was switched. Duplicating never creates
  a second source table.
- **Notes on tasks.** Attach a full note to any task from the row menu:
  **New note**, **Link existing note**, or open the attached one. It opens
  inline at the bottom of the page.
- **Due date and done date:**
  - Tasks have a due date, shown on the Calendar view. The Due date column
    is hidden by default and can be shown per table.
  - Overdue, unfinished tasks are highlighted (or hidden, by setting).
  - Done tasks record their done date, and leave the calendar unless *Hide
    from calendar when done* is off.
- **Hidden plumbing columns.** Columns used internally for hierarchy are
  hidden in the journal view.

### Mobile and touch

- **Mobile database editing is on by default.**
- **List and Calendar views work by touch:**
  - row focus and drag target
  - per-day "New row"
  - month navigation
  - filter menu sizing
- **Tappable checkbox.** The task checkbox can be tapped on iOS, and ticking
  it doesn't raise the keyboard.
- **A clearer "+ Add view" button** in the view bar.
- The mobile keyboard toolbar's database tools are in [pr/30](../pr-30/).

### Performance and data safety

- **Cells are written in place.** Cells and task status were stored by
  replacing the whole `cells` map. Every edit wrote a full copy of the table
  into the doc history. A real journal doc grew to **116 MB** and crashed the
  app.
- **Filtered views read less.** A filtered view reads only the columns its
  filter uses. Typing in a title no longer re-filters every row.
- **Drags write less.** Dragging a row writes only the hierarchy cells that
  actually changed, in one transaction. A drag was writing every row's
  hierarchy cells.

## How it works

- **Data view (`blocksuite/affine/data-view`):**
  - the List view
  - hierarchy rendering
  - touch handling
  - `filterRefNames()` for property-scoped filtering
- **Database block (`blocks/database`):**
  - task status and hierarchy columns
  - `recomputeHierarchyMetadataAfterMove`
  - in-place cell writes
  - promotion from to-do lists
- **`blocks/database-view-ref`:**
  - the per-instance view reference
  - Journal Todo commands (`slash-menu.ts`)
  - `journal-todo-carryover.ts` (copy undone tasks)
  - the duplicate middleware that points template copies at the current
    table
- **`blocks/database-note-property`:** the note attached to a row.
- **Core (`packages/frontend/core`):**
  - the journal store reads the Journal Todo source from the workspace root
    doc
  - the due-date settings
  - Calendar view integration

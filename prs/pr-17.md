## Why

On Linux, middle-click pastes the X11 primary selection at the raw DOM
caret. That bypasses BlockSuite's paste handling. Text can end up in the main
document when an edgeless note was only selected. AFFiNE has a setting,
`enableMiddleClickPaste`, to block this. In this fork a refactor once deleted
the condition that checks it, and the setting silently stopped working.

## What changes

The setting this protects is **Settings → Editor → General → Middle click
paste** ("Enable default middle click paste behavior on Linux"), shown on
Linux only:

- **Off** (the default): a middle click in the editor does not paste.
- **On:** a middle click pastes the primary selection, as in other Linux apps.

Both the setting and the check that applies it are already in upstream
`canary`. This PR keeps them working and doesn't change their behaviour. The
check moves into a named, exported function,
`shouldSuppressMiddleClickPaste()`, with a unit test, so it can no longer be
lost by accident.

## Testing

Unit tests: `middle-click-paste.spec.ts`.

## Open items

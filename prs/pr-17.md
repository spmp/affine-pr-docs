# pr/17: Regression guard for the middle-click paste setting
{: .no_toc }

Branch `pr/17-middle-click-paste` · base `pr/15` (`pr/16` is empty) ·
5 commits · 2 files, +57
{: .fs-3 .text-grey-dk-000 }

## Why

On Linux, middle-click pastes the X11 primary selection at the raw DOM
caret. That bypasses BlockSuite's paste handling. Text can end up in the main
document when an edgeless note was only selected. AFFiNE has a setting,
`enableMiddleClickPaste`, to block this. In this fork a refactor once deleted
the condition that checks it, and the setting silently stopped working.

## What changes

Nothing a user sees: behaviour is the same as upstream `canary` today. The
check moves into a named, exported function,
`shouldSuppressMiddleClickPaste()`, with a unit test. The setting can no
longer be lost by accident in the same way.

## Testing

Unit tests: `middle-click-paste.spec.ts`.

## Open items

This is a small, test-only change. Offer it upstream only if the maintainers
want the guard. Otherwise drop the branch.

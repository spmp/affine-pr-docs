## Why

Some content belongs in more than one place: a weekly checklist, a shared
set of notes, a task table that several pages should show. AFFiNE can link to
a whole doc, or embed a frame from the same doc, but it can't show a single
block **live and editable** somewhere else. The only option is copying, and
copies drift apart.

This PR adds block references. One block, the source, is shown in place in
any number of other spots, on the same page or another page. Edits made
anywhere write back to the source.

## What changes

### Note references

- **Insert a reference.** In page mode:
  - `/Note: <name>` inserts a reference to an existing note on this page.
  - `/New note` creates a note and inserts a reference to it.
  - `/Reference` picks a note, frame or table from another doc.
- **The referenced note is fully editable in place:**
  - typing and the full slash menu
  - undo and redo
  - paste
  - selection
  - the caret on iOS
- **Its own look.** Each reference has a name, a background colour and an
  optional border. Global defaults are in *Settings → Editor → Note*.
- **Toolbar:**
  - toggle border
  - background colour
  - **Move to page…** moves the note to another page; references keep
    working
  - delete
- **Turn a note into a sub-page**, keeping it linked.

### Database and frame references

- **Tables can be referenced like frames.** `/Table: <name>` on the same page,
  or `/Reference` from another doc.
- **Edits write back.** Edits in a reference go to the source table.
- **View settings persist.** A reference's view settings survive a reload.
- **Cross-page frame references** work the same way.

### Nothing is lost when a page is deleted

When a page holding a referenced note or table is permanently deleted, the
source block is first **rescued** into a page that still references it.

### Search and the reference picker

- **The picker searches every doc.** The cross-doc picker lists notes, frames
  and tables across the workspace by name, and can be browsed with an empty
  query.
- **Search indexes their names.** The search index now stores frame titles,
  note names and table names.
- **Fix: docs missing from search.** A doc whose page title was missing
  could crash the crawler. It was then marked "indexed" with no blocks and
  never searchable again. The crash is fixed and the indexer version is
  bumped, so affected docs are re-indexed.

## How it works

- **New blocks:**
  - `affine:note-ref` in `blocks/note-ref`
  - `affine:database-ref` in `blocks/database-ref`
  - `affine:surface-ref`, extended in [pr/13](../pr-13/) and here for
    cross-doc use
- **A stable source.** Each reference stores `refDocId` and `refBlockId`. The
  source is found by id, so moving the source block within its doc doesn't
  break the reference.
- **Nested editors.** A reference mounts the source block in a nested editor
  bound to the source doc's store.
  - `std` changes keep an outer editor from taking activation away from a
    nested one.
  - Focus, selection and undo stay scoped to the editor the user is in.
  - Inserting a note reference that would contain itself (directly or
    through other references) is refused.
- **Editable boundary.** `contenteditable=false` is set on the page root, so
  the nested editable area is its own editing host. This fixes cross-block
  selection and iOS caret placement.
- **Caret on iOS.** The referenced note's inner `affine-note` renders as
  `display: block`. As an inline element, iOS taps inside it never moved the
  caret.
- **Paste.** The paste target is resolved from the model (`store.getParent` +
  child index), not the DOM view. Paste in the source note now lands at the
  cursor when the same note is also shown elsewhere on the page.
- **Moving and rescuing:**
  - `note-move-service.ts` moves a note to another page.
  - `docs.ts` rescues referenced notes and tables before a permanent delete.
- **Search.** The reader (`packages/common/reader`) extracts reference names.
  `cross-doc-reference-candidates.ts` feeds the picker.

# pr/40: Compress static assets and API responses
{: .no_toc }

{: .fs-3 .text-grey-dk-000 }

## Why

A self-hosted server without a compressing reverse proxy sends the web app's
JavaScript bundles and its GraphQL/JSON responses uncompressed. On a phone
connection, first load is slow.

## What changes

The server compresses responses with the `compression` middleware:

- static assets served by the server
- API responses (GraphQL and REST)

Nothing changes for deployments that already compress at the proxy.
`compression` skips responses that are already encoded.

## How it works

- `app.use(compression())` is registered in two places:
  1. **First thing in `StaticFilesResolver.onModuleInit`.** That module
     registers its static routes during `NestFactory.create()`, before
     `server.ts` runs, so middleware added only in `server.ts` would never
     wrap them.
  2. **In `server.ts`,** for API responses, before the body parsers.

## Testing

By hand: checked `Content-Encoding` on assets and API responses.

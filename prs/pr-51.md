# pr/51: Toasts work after their editor is gone
{: .no_toc }

Branch `pr/51-toast-container` · base `pr/50` (no dependency on it) ·
1 commit · 1 file, +4
{: .fs-3 .text-grey-dk-000 }

## Why

`toast()` creates its container once, next to the first editor that shows a
toast, and reuses it after that. When that editor goes away, for
example after navigating to another page, the container is detached from
the document. Every later toast is added to a detached element and never
shown.

## What changes

`toast()` checks that its container is still in the document, and creates a
new one if not. Toasts show again after navigating between pages.

## How it works

The fix is in `blocksuite/affine/components/src/toast/toast.ts`: an
`isConnected` check before the cached container is reused.

## Testing

By hand: toasts show after moving between pages.

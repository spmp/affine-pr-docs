## Why

Typing a list of tasks into a table means adding a row, clicking into it and
typing, over and over. In a List view Enter already adds the next row. This
gives tables the same option, for people who want it, without changing
what Enter does for everyone else.

## What changes

- **A setting:** Settings → Editor → General → **Enter adds a new row in
  database tables**. Off by default.
- **When on**, Enter while editing a text or number cell (title, rich text,
  text, number) in a table:
  - adds a row below the current row (after any rows indented under it),
    at the same indent level and under the same parent;
  - starts editing the same column in the new row.
- **Shift+Enter** is still a new line in text cells.
- **When off**, Enter finishes editing the cell, as before.
- Works in tables shown through references too (e.g. the Journal Todo).

## How it works

- `databaseEnterAddsRow` in the editor settings, read by the database block
  from the nearest editor that has the settings (a reference's nested editor
  doesn't, so it looks outwards to the page's).
- Cells call a new `commitByEnter()` on Enter; the table's cell container
  decides between finishing editing and adding a row.
- The List view's "add a row after this one, same level" moved to a shared
  helper used by both views.

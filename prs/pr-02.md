## Why

The edgeless shape, pen and connector tools each offer one fixed set of
colours, set separately for line and fill. Diagrams that need a consistent
look, such as a set of soft pastels or a bold set, or that need gradient
fills, have to be recoloured shape by shape.

## What changes

- **Palette sets.** The shape toolbar has a palette selector. Each palette is
  a set of matched line and fill swatches. Built-in palettes:
  - AFFiNE (the current colours)
  - Material light
  - Material gradient (each colour fades to a darker shade)
  - Bold
- **Gradient fills.** Shapes can have a gradient fill with a direction. The
  colour picker can set the gradient colours and direction.
- **The same palettes everywhere.** The pen (brush) and connector menus use the
  same palettes as shapes.
- **Palettes in Settings.** *Settings → Appearance → Palettes*:
  - add, edit and reorder palettes
  - reset them to the defaults
  - keep custom colours
  - choose the default palette

  Palettes are stored per workspace.
- **Fixed tail swatches.** Every palette ends with white, black and
  transparent.
- **Line and fill visibility.** A palette can define its line and fill
  visibility defaults, and the drawing tools follow them.
- **Separate style memory.** Rectangles, rounded rectangles, ellipses and
  triangles each remember their last style. Before this, some shared one
  memory bucket.

## How it works

- Palette definitions live in the theme: `ShapePalettes` in
  `blocksuite/affine/model/src/themes/default.ts`.
- `ShapePaletteStyle` gains `gradientFinal` and `gradientDirection`. The
  shape renderers (canvas and DOM) draw gradients when these are set.
- `gfx/shape/src/draggable/palettes.ts` and `palette-memory.ts` hold the active
  palette and per-shape style memory.
- `get-last-props-key.ts` normalises shape names to their last-props bucket.
- The settings UI is `palette-settings.tsx` under *appearance*. It writes
  workspace-scoped storage that the toolbar menus read.
- The pen and connector menus load the workspace palettes once the workspace
  id is available. This is guarded, because the id is not always set when
  `connectedCallback` runs.

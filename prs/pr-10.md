## Why

Technical diagrams use vendor icon sets: AWS, GCP, Azure, Cisco, Kubernetes,
racks and network gear. draw.io ships these as stencil libraries. Making them
available in AFFiNE means diagrams don't have to be drawn in another tool and
pasted in as images.

## What changes

- **About 8,900 stencils in about 200 categories** in the shape browser,
  including:
  - AWS (aws3, aws4)
  - GCP
  - Alibaba Cloud
  - IBM Cloud
  - Cisco
  - Citrix
  - Veeam
  - Azure and Microsoft (mscae)
  - Kubernetes
  - Office
  - network and rack gear
  - web logos and icons
  - fluid power
- **Thumbnails.** Library shapes show thumbnails in the browser and can be
  searched.
- **Lazy loading.** Library stencils are loaded only when used, so they don't
  slow the app's first load.

## How it works

- `scripts/drawio-library-manager.mjs` generates the catalogue
  (`drawio/library-catalog.ts`) and the stencil data. The stencils are split
  into three chunks: `library-stencils-{a,bm,nz}.ts`.
- **Startup cost.** The first approach bundled everything into the main entry
  chunk, which made it about 61 MB and delayed every page load, login
  included. The design (BMAD story 10-0) keeps only the small catalogue in the
  entry chunk. The stencil chunks are dynamic imports, loaded on first use.
- Shape rendering waits for its stencil to load instead of drawing an empty
  shape.
- The generated files are excluded from oxlint and prettier.

## Testing

Unit tests: `stencil-lazy-loading.unit.spec.ts`, checking that the stencils
are not in the entry chunk and that they load when used.

## Notes for reviewers

- **Size.** Most of the diff is generated data. Review the generator script
  and the loading code. The data files only need a sanity check.
- **Typechecking** this branch needs a larger Node heap, as CI already uses:
  `NODE_OPTIONS=--max-old-space-size=14384`.
- **Licence.** The stencils come from draw.io's libraries. Please check that
  their licence is compatible before merging.
- Upstream may prefer the stencil data served as static assets or a separate
  package instead of TypeScript modules. Happy to change this.

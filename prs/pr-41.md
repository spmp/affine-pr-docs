# pr/41: Installable, offline-capable PWA
{: .no_toc }

Branch `pr/41-server-pwa` · base `pr/40` · 4 commits · 30 files, +3,537
{: .fs-3 .text-grey-dk-000 }

## Why

On iOS, a self-hosted AFFiNE "added to Home Screen" has no service worker.

- **Offline.** With no network, such as airplane mode or a bad signal, it
  shows an error instead of the app.
- **iOS reclaims it.** When iOS reclaims the backgrounded app, reopening it
  needs the network again.

AFFiNE already keeps documents locally. It is the **app shell** that can't
load offline.

## What changes

- **A service worker** for the web and mobile apps.
  - **Offline launch.** The app shell is precached, so the app opens
    offline, including from the home-screen icon.
  - **Lazy chunks.** These are cached as they are used.
- **Update notice.** When a new version is deployed, the user sees a
  notice and chooses when to reload. The app is never swapped under them
  mid-edit.
- **Manifest and icons:**
  - proper app icons, including maskable icons
  - a sharp Apple touch icon
- **The server** serves the service worker and manifest for the web and
  mobile builds.

## How it works

- `apps/{web,mobile}/src/service-worker.ts` uses Workbox.
  `tools/cli/src/bundle.ts` injects the precache manifest at build time
  (`injectServiceWorkerManifest`).
- `service-worker-route.ts` routes navigations **before** the precache
  lookup. The home-screen launch URL (`/?source=pwa`) then falls back to the
  cached app shell. Before this, it missed the precache and failed offline
  with "FetchEvent.respondWith received an error: TypeError: Load failed".
- `register-service-worker.ts` and `service-worker-update-notice.ts` handle
  registration and the user-prompted update.
- `doc-renderer/controller.ts` serves the HTML shell with the new icon links.

## Testing

- Unit tests (web and mobile):
  - service worker routing
  - registration
  - the update notice
- On device: iPhone, offline launch in airplane mode, including pages not
  opened that day.

## Open items

- **Cold lazy chunks.** After a deploy, a lazy chunk is cached only once it
  has been used online. A view never opened since the update won't load
  offline. Candidate fix: precache all chunks below a size limit when a new
  version installs.
- **iPad.** iPadOS reports a desktop user agent, so tablets get the desktop
  app rather than the mobile app.
